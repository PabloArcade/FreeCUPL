FreeCUPL 2.2.0 USER GUIDE

FreeCUPL consists of two programs with the command lines of the WinCUPL
5.0a command-line tools.  freecupl compiles CUPL source (.pld) into a
JEDEC fuse file (.jed) and optionally a documentation file (.doc), a
listing (.lst), a macro expansion (.mx) and an absolute file (.abs);
with -s it also runs the simulator.  freecsim applies test vectors
(.si) to a compiled design (.abs) and writes a listing (.so), a waveform
file (.wo) and optionally the test vectors into the JEDEC file.  The
helper tools jedsim, equiv and jedtool are described in section 7.  On
Windows, freecuplw is an editor and front end for both (section 8).

1. FREECUPL

    freecupl [-flags] [library] [device] file[.pld]

If file has no extension and does not exist as given, file.pld and then
file.PLD are tried.  device is a mnemonic from section 9 and overrides
the Device statement of the source.  library is accepted and ignored;
an argument is taken as the library when -u is given, when there are
three positional arguments, or when it ends in .dl.

Single-letter flags may be combined after one dash (-jaxf), in either
case.

Output flags:

  -j     write the JEDEC file NAME.jed.  It is also written when none
         of -x -l -e -a is given.
  -x     write the documentation file NAME.doc (expanded product terms,
         symbol table)
  -f     add the fuse plot to NAME.doc (writes NAME.doc without -x too)
  -l     write the listing SOURCE.lst (numbered source and messages)
  -e     write the macro expansion SOURCE.mx (source after the
         preprocessor)
  -a     write the absolute file NAME.abs for freecsim
  -s     compile, write NAME.abs and simulate SOURCE.si, writing
         SOURCE.so and SOURCE.wo; with -j the test vectors are appended
         to the JEDEC file
  -n     name the outputs after the source file, not the Name item

NAME is the value of the Name header item.  With -n, or when there is no
Name item, the source file name without extension is used; with no Name
and no -n the name is no_name and warning 0009cc is given.  SOURCE is
always the source file name without extension.  Outputs are written in
the directory of the source file.

Compilation flags:

  -m0    no minimisation
  -m1    quick minimisation (default), with WinCUPL's term counts
  -m2 -m3 -m4
         stronger minimisation (Espresso-style cover).  May
         fit designs that WinCUPL rejects for too many product terms.
  -kb    choose for each output the polarity needing fewer product
         terms (see bugs B001 and B002)
  -g     program the security fuse (*G1)
  -u     the next positional argument is the library (ignored)

The MIN statement sets the minimisation level of single variables.

The flags -w -b -h -i -p -c -d -r -o -q -kd -ks -kx are accepted so
that existing command lines keep working.  They have no effect; the
WinCUPL output formats they select are not implemented.  Any other
letter, or -m5 and above, is rejected with [0007ck] invalid flag.

Options given as separate arguments:

  -compat-refdefect  reproduce WinCUPL 5.0a exactly, including its
                     bugs (section 5)
  -fix               correct the bugs: the default, accepted for
                     scripts written for 1.0.0
  -simlatch          with -s, simulate latched outputs and registered or
                     latched inputs (timing not verified; by default
                     they show X, as in WinCUPL's simulator)
  -devices           print the supported mnemonics and exit
  -V, --version      print "FreeCUPL 2.2.0 (DARKSOFT)" and exit

Without arguments freecupl prints a usage summary and exits with 1.

The exit status is 0 when the requested outputs were written; warnings
do not change it.  It is 1 on errors, on an invalid flag, or when the
simulation run by -s reported errors.  After an error only the listing
and the macro expansion are written, if requested.

Examples:

    freecupl -jxf counter.pld      JEDEC and .doc with fuse plot
    freecupl -jn g22v10 counter    compile for g22v10, counter.jed
    freecupl -jas counter          compile and simulate counter.si
    freecupl -compat-refdefect -jx counter
                                   exactly as WinCUPL 5.0a, bugs included

The language is WinCUPL's, including what it accepts and rejects.  The
words APPEND, CONDITION, DEFAULT, FIELD, FLD, FUNCTION, GROUP, IF, MIN,
NEXT, NODE, OUT, PIN, PINNODE, PRESENT, PROPERTY, SEQUENCE, SEQUENCED,
SEQUENCEJK, SEQUENCERS, SEQUENCET, TABLE and the header item names
cannot be used as names, in any letter case.  ELSE, JUMP and MACRO
can.  FUSE is only accepted as a name in PIN and PINNODE statements.
docs/BUGS.txt, part A, has the details.


2. FREECSIM

    freecsim [-flags] [library] [device] file[.si]

freecsim reads file.si and the absolute file file.abs written by
freecupl -a or -s.  Each name is tried in lower case, then in upper
case.  device, when given, must be the device of the absolute file
([0010sa] expecting device; [0007sa] for an unknown mnemonic).  library
is ignored.  The waveform file file.wo is always written.  The formats
of .si, .so, .wo and .abs and the simulation rules are described in
docs/SIMFMT.txt.

  -l     write the listing file.so
  -v     also show the listing on the terminal (writes file.so)
  -j     append the test vectors to NAME.jed (NAME from the design's
         Name item), or to file.jed with -n
  -n     see -j
  -u     the next positional argument is the library (ignored)
  -w -d  accepted, no effect (there is no waveform display)

Options given as separate arguments:

  -compat-refdefect  reproduce WinCUPL 5.0a's simulator exactly,
                     including its bugs (B025 to B028, B030, B039,
                     B040)
  -fix               correct the bugs: the default
  -simlatch          simulate latched outputs and registered or latched
                     inputs (timing not verified)
  -fuses FILE.jed    simulate the fuse map of FILE.jed instead of the one
                     in the absolute file; the fuse count must match
  -info              print the signals of the design (name, pin,
                     polarity, role) and exit
  -V, --version      print the version and exit

Other flags are rejected with [0007sk] invalid flag.  The exit status is
0 when the simulation ran without errors and 1 otherwise, including a
failed expected value ([0019sa] user expected ...).

Some simulation models follow WinCUPL's simulator and cannot be checked
against the fuse map: the RA parts, the MegaPALs, parts with latches
only, the PEEL18CV8 reset levels, input registers and latches, and the
ATV5000.  For these the listing says "simulation model for <device>
follows WinCUPL and is not verified against the data sheet".


3. FILES

The source (.pld) is CUPL as accepted by WinCUPL 5.0a: header items,
PIN, PINNODE, NODE, FIELD, equations with extensions, TABLE, SEQUENCE,
SEQUENCED, SEQUENCEJK, SEQUENCERS, SEQUENCET, CONDITION, FUNCTION,
APPEND, MIN, FUSE, PROPERTY, and the preprocessor commands $DEFINE
$UNDEF $INCLUDE $IFDEF $IFNDEF $ELSE $ENDIF $REPEAT $REPEND $MACRO $MEND
and {arithmetic}.  LF and CRLF line ends are both read.  An $INCLUDE file
is looked for in the current directory, then in the source's directory.

The simulation input (.si) is in CSIM format: header, ORDER:, BASE:,
VECTORS:, the commands $MSG $REPEAT $TRACE $SIMOFF $SIMON $EXIT $OUT, and
the test values 0 1 C K P L H Z X N * and quoted field values.

Output files:

  .jed   freecupl -j   JEDEC (JESD3) fuse file: header, QP QF G F L C
                       fields, transmission checksum; test vectors (QV
                       P V) with -s
  .doc   freecupl -x   expanded product terms, symbol table, fuse plot
                       with -f
  .lst   freecupl -l   numbered source and messages
  .mx    freecupl -e   source after the preprocessor
  .abs   freecupl -a   the compiled design for freecsim, in FreeCUPL's
                       own text format (docs/SIMFMT.txt); WinCUPL's
                       binary absolute files cannot be read
  .so    freecsim -l   simulation listing (also freecupl -s)
  .wo    freecsim      waveform data (also freecupl -s)

The headers of .jed, .doc, .lst and .so name the version, "FreeCUPL
2.2.0 (DARKSOFT)", and the creation date.

If the environment variable SOURCE_DATE_EPOCH is set to a number of
seconds since 1970-01-01 UTC, that time is written as the creation date
instead of the current local time.  SOURCE_DATE_EPOCH=0 gives "Thu Jan
1 00:00:00 1970".  The JEDEC checksums do not depend on the date.


4. MESSAGES

Messages have the WinCUPL form "[nnnnXX] text", with line(n) when they
refer to a source line.  The two letters give the stage: ck command
line, cx preprocessor, ca parser, cb fitter, cc output and fitting
limits, sk and sa simulator.  Messages starting with "Please note:" or
"Warning:" do not stop the compilation.  Any other message is an error;
the compilation ends with "Fatal errors encountered ... compilation
aborted" and exit status 1.

Codes 0901 to 0908 are FreeCUPL's own.  They report a place where
WinCUPL 5.0a does something its language reference does not describe,
and what FreeCUPL does there.

5. WINCUPL BUGS AND -COMPAT-REFDEFECT

Since 2.0.0 FreeCUPL corrects the known bugs of WinCUPL 5.0a.  Where a
design meets one, the JEDEC file or the simulation follows the source as the
CUPL language reference defines it, and a message names the bug.  For
every other design the JEDEC file makes the device behave as WinCUPL's
does.

-compat-refdefect reproduces WinCUPL 5.0a exactly, bugs included, so
that parts programmed from WinCUPL's files and existing test benches
keep their behaviour.  This was the default of FreeCUPL 1.0.0; make
FIX_DEFAULT=0 builds tools with that default.  -fix is accepted and
does nothing.

The known bugs are numbered B001 to B040 and described with an example
and the correct behaviour in docs/BUGS.txt.  By default the message
reads:

    [0905cb] Warning: deviates from WinCUPL (bug #B013 fixed): F18V8ZS:
    output enable of pin 19 (y) without .OE: always enabled (CUPL
    default)

With -compat-refdefect:

    [0905cb] Warning: WinCUPL bug #B013: F18V8ZS: the output enable of
    pin 19 (y) is left false when no .OE is given; reproduced for
    -compat-refdefect

Where the device cannot do what the source asks and WinCUPL writes a
wrong fuse map, the default rejects the design (0902cb, 0907cb,
0013cc).  Where WinCUPL stops with an error or crashes (B008, B029,
B031), -compat-refdefect stops with the same error and the default
gives the documented result.  Both modes work for the compiler and the
simulator (freecupl -s, freecsim).

Behaviour that WinCUPL documents, or that is odd but not shown to be
wrong, is not treated as a bug and is the same in both modes (see
docs/BUGS.txt, parts A and B).


6. LIMITATIONS

FreeCUPL supports the 327 mnemonics of section 9.  WinCUPL 5.0a compiles
93 more mnemonics to a JEDEC file without an external fitter.  FreeCUPL
has no description of these parts and rejects them with [0006ca] device
not in library.  The mnemonics not supported, with the reason:

  PLS/IFL sequencer and FPLA parts (37).  Programmable OR array or
  complement array, S/R and J/K buried registers.  They need a PLA
  fitter, which FreeCUPL does not have.
      f100 f103 f105 f151 f153 f155 f157 f159 f161 f167 f168 f173 f179
      f253 f273 f405 f415 f473 f501 f502 f506 f507 f529 f839 f30k12
      f30s16 f42va12 f48n22 f9800 f167lcc f168lcc f173lcc f179lcc
      f42va12lcc f473lcc f506lcc f507lcc

  GAL6001, GAL6002 (4).  FPLA with a programmable OR array and buried
  state macrocells: PLA fitter, as above.
      g6001 g6001lcc g6002 g6002lcc

  ispGDS22 (1).  A switch matrix, not an AND array.
      gds22

  EPLDs EP300 to EP1800 (12).  Feedback multiplexers, T registers and
  global clocks are not described.
      ep300 ep320 ep312 ep324 ep600 ep900 ep1200 ep1800 ep312lcc
      ep324lcc ep600lcc ep900lcc

  Parts beyond the generic macrocell (16).  S/R, T or latch registers,
  observability, buried logic.
      p18u8 p22ip6 p22v10s p23s8 p23sv8 p29m16 p29ma16 p32vx10 pc224
      plx448 xl78c800 p22v10slcc p29m16lcc p29ma16lcc p32vx10lcc
      pc224lcc

  Parts with latched outputs (10).  The latch structure is not
  described.
      p1016lm4 p1020eg8 p1020g8 pc960 p7b336 p7b337 p7b338 p7b339
      p1020eg8lcc p1020g8lcc

  Irregular arrays (9).  Outputs share product-term rows; the fuse map
  is not established.
      p1012c4 p1016c4 p1016p4 p1016rm4 p1020rp4 p6l16 p8l14 p16p4c
      p16p4clcc

  Others (4).  p7c332: XOR with programmable polarity, the description
  did not pass verification.  The other three have no description yet.
      p14r21 p7c330 p7c331 p7c332

ATV5000 (v5000).  Inputs: pins 1, 2, 32, 34, 35, 36, 66, 68.  I/O
cells by quadrant: pins 4-15 and 17; 18, 19 and 21-31; 38-49 and 51;
52, 53 and 55-65.  Clock pins 2, 32, 36, 66 and latch clock pins 1, 34,
35, 68, one of each per quadrant.  Each I/O cell has a second register,
PINNODE 105 down to 93 for pins 4 to 17, 106 to 118 for pins 18 to 31,
131 down to 119 for pins 38 to 51, 132 to 144 for pins 52 to 65.  Buried
cells: PINNODE 74 down to 69 (quadrant 1), 75 to 80 (quadrant 2), 85
and 86 (quadrant 3); WinCUPL knows no others and FreeCUPL follows it.
A register is read by its name only inside its own quadrant; a pin (a
combinational output, or NAME.io of a registered one) is read anywhere.
Extensions: .d .t .ck .ce .ar .ap .oe on the left, .io .lq .iol on the
right.  A sum has 4, 5, 9 or 13 product terms, of which 1, 2, 3 or 4
may read I/O pins; the second register has 4 (1), a buried cell 5 (1).
The other terms read inputs and the registers of the quadrant.
The simulation model of the ATV5000 is not verified.  No device was
available, WinCUPL's simulator does not work from the fuse map on this
part (B036, B039, B040), and the correction of B036 follows the data
sheet only.  Check a programmed part before relying on the simulation.

Devices for which WinCUPL calls an external fitter (the ATF15xx CPLDs
and others), PROMs and the virtual device are not supported.

Latched outputs and registered or latched inputs simulate as X, as in
WinCUPL's simulator.  -simlatch simulates them, but its timing has not
been checked against hardware.

With -kb, the polarity WinCUPL picks is not reproduced on a few designs
(ranges, XOR lists, some registered PEEL, RA and ATV outputs at -m0).
The JEDEC file is then correct for the source with bug B001 applied,
but may differ from WinCUPL's.

-m2 to -m4 can find smaller covers than WinCUPL and so fit designs that
WinCUPL rejects with 0006cc.

Not implemented: the output formats of -b -h -i -p -c -d -r -o -q,
reading WinCUPL's binary absolute files, the waveform display.

The macOS build is only tested by the project's continuous integration.


7. HELPER TOOLS

These take a JEDEC file of any supported device.  The device comes from
the file's Device line or from -d.

    jedsim [-d device] [-D file.dev] [-l | -c | -L] [file.jed]

Fuse-level simulator.  -l prints the decoded configuration as equations
per pin, -c checks the checksums, -L lists the device descriptions.
Otherwise it reads commands from standard input: "v <chars>" with one
character per pin (0 or 1 drive, C clock pulse, H L Z expected), "set
P=V ...", "preload P=V ...", "clock", "eval", "state".

    equiv [-d device] [-D file.dev] [-n bits] [-r points] [-S seqs]
          [-s seed] [-i pins] [-q] a.jed b.jed

Compares the behaviour of two JEDEC files for one device.  The check is
exhaustive when the relevant inputs and register bits number at most
-n (22), otherwise it uses random points and clocked sequences.  -i
gives pins to ignore.  Exit status 0 equivalent, 1 different, 2 error.

    jedtool check FILE | fuses FILE | rewrite IN OUT | diff A B |
            flip IN OUT N... | stdheader IN OUT

JEDEC utilities: check the checksums, print the fuse map, write a file
again, list differing fuses, invert fuses.


8. FREECUPLW (WINDOWS)

freecuplw.exe is an editor and front end for Windows XP SP3 and later.
It does not contain the compiler.  It runs freecupl.exe and freecsim.exe
from its own directory and shows what they print, so a design gives the
same files and messages as on the command line.  Keep the three programs
in one directory.  It also runs on Linux and macOS under Wine, where it
was tested.

    freecuplw [file ...]

Files.  Files are opened from the command line, with File Open, from the
recent files at the end of the File menu, or by dropping them anywhere
on the window, several at a time.  Each file has a tab (Ctrl+Tab, Alt+1
to Alt+9).  The output files .jed .doc .lst .so .wo .abs .mx are opened
read only; anything else can be edited.  File New starts a source with
the header items.

Editor.  Undo and redo, find and replace (Ctrl+F, Ctrl+H, F3), go to
line (Ctrl+G).  The status bar shows line and column and whether the
file has CRLF or LF line ends; the file is saved as it was read (a file
with both kinds, in the more frequent one).  Text is read and written
in the system code page.  The View menu sets the font, the tab width
and syntax colouring (comments, keywords, numbers); files of more than
400000 characters are not coloured.  The font is used for the editor
and the message pane; it is Consolas 10 where that is installed (Windows
Vista and later) and Courier New 10 otherwise.

Insert Device (Ctrl+D) lists the supported mnemonics with pin count and
part name.  The search field takes parts of either, separated by blanks
("16v8 complex").  Insert replaces the Device statement of the file, or
puts one on a new line at the caret when there is none.

Compile (F7) saves the changed files and runs freecupl on the source of
the active tab; on a .si tab, on the .pld of the same name.  Simulate
(F8) compiles with -a and then runs freecsim on the .si of the same
name.  Stop (Ctrl+Break) ends the running program.

Options (F9) sets the flags of both programs:

  JEDEC file, Documentation, Fuse plot, Listing,
  Absolute file, Macro expansion           -j -x -f -l -a -e
  Name the outputs after the source file   -n
  Minimisation                             -m0 to -m4
  Device                                   the device argument
  Pick the output polarity                 -kb
  Program the security fuse                -g
  WinCUPL compatibility                    -compat-refdefect
  Simulate after compile                   -s on Compile, when the .si
                                           file exists
  Listing (.so)                            freecsim -l
  Test vectors into the JEDEC file         freecsim -j
  Simulate latches (not verified)          -simlatch

As on the command line, the JEDEC file is also written when none of the
other outputs is asked for.  With "Keep these options for this file
only" the options are stored for the source of the active tab and used
for it alone; otherwise they are the options of every file that has
none of its own.

Messages.  The lower pane shows the command line, the output of the
program, the files it wrote and a summary line, "Compile: OK - 0 errors,
1 warning".  A double click on a message with a line number goes to
that line of the source (of the .si file for simulator messages); on a
file name it opens the file.  freecsim writes its messages into the
listing only: they are shown as "name.so(line): message" and lead to
that line of the listing.  The right mouse button copies a line or the
whole pane.

Viewers.  The View menu opens the source, the simulation input and the
.jed, .doc, .lst and .so files of the active design (Ctrl+1 to Ctrl+4
for the outputs).  Open viewers are read again after every run.

Help shows this guide and the version of freecupl.exe.

Settings are kept in freecuplw.ini in the directory of the program:
window position, font, recent files, options.  The registry is not
used.  If the directory cannot be written the settings are lost at
exit; delete the file to get the defaults back.

Limits: file names must be in the system code page; no printing; the
waveform file (.wo) is shown as text.  Run as administrator, the
program cannot take dragged text (Windows keeps programs without
administrator rights, Explorer among them, from dragging to it; files
can still be dropped); the About box says when it runs that way.
